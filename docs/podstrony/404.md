# Strona błędu 404

[Spis podstron](README.md)

## Kiedy jest wyświetlana

Źródło: `pages/404.html`. Lokalny serwer zwraca ten dokument ze statusem HTTP 404
dla nieznanego zasobu przy żądaniu GET/HEAD akceptującym HTML.
Przy żądaniu nieoczekującym HTML odpowiedź może być zwykłym komunikatem tekstowym,
a nieznany endpoint API zwraca osobny błąd JSON.
Otwarcie istniejącego pliku `404.html` bezpośrednio nie jest tym samym testem co żądanie nieistniejącego adresu.

## Zawartość

- Wspólna nawigacja, wybór języka i motywu.
- Numer 404, metaforyczny nagłówek o niepowstałym kadrze i informacja o braku lub przeniesieniu strony.
- Przycisk „Wróć do bazy” prowadzący na Start.
- Dekoracyjne tło zgodne z publicznym wyglądem.

Strona nie ma stopki ani pływającego skrótu kontaktowego. Żaden element menu nie jest oznaczony jako bieżąca podstrona.

## Adresy zasobów i indeksowanie

`<base href="/">` pomaga poprawnie pobierać zasoby również z głęboko zagnieżdżonego błędnego adresu.
W źródle jest specjalna obsługa prefiksu repozytorium dla hosta GitHub Pages.
Eksporter dodaje własny prefiks; należy przetestować również wersję pod `/portfolio/`.
Meta `robots=noindex` informuje roboty, żeby nie indeksowały dokumentu błędu.

## Edycja

Nie ma edycji 404 ani szkiców tej strony w panelu administratora.
Teksty PL/EN, przycisk i strukturę zmienia się w `pages/404.html`; wygląd karty błędu w `portfolio.css`.
Wspólne zachowania obsługują `portfolio.js`, `theme.js`, `router.js` i `neon.js`.
Zmiana nie wymaga przebudowy bazy; wersja Pages wymaga ponownego eksportu i publikacji.

## Scenariusze sprawdzenia

1. Otwórz nieistniejący adres oraz nieistniejący adres z kilkoma segmentami.
2. Sprawdź kod 404 odpowiedzi serwera, nie tylko napis „404”.
3. Upewnij się, że style, ikony i menu działają pod tym adresem.
4. Przełącz język i motyw, a potem wróć na Start.
5. Powtórz pod prefiksem eksportu Pages.

„Projekt niedostępny” i „Album niedostępny” są stanami danych na innych podstronach,
nie automatycznie tym dokumentem 404.
